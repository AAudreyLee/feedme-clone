# 페이지 → Markdown 변환과 LLM 전달

## Decisions

- 본문 추출은 `defuddle`로 합니다. 페이지 가져오기와 변환은 서버(`app/api/convert`)에서만 합니다.
- `defuddle/node`에 URL 문자열을 넘기지 않습니다. 서버에서 받은 HTML을 `linkedom`의 `parseHTML`로 문서로 만든 뒤 `Defuddle(document, url, { markdown: true })`로 넘깁니다.
- 복사, `.md` 다운로드, LLM 전달의 본문은 모두 `# 제목` + 본문 전체로 같습니다. 복사와 다운로드에는 프롬프트를 넣지 않습니다.
- LLM으로 보낼 때 프롬프트는 본문 앞에 빈 줄 하나로 구분해 붙입니다. 고르지 않으면 본문만 보냅니다.
- 전달 텍스트가 URL 한도(인코딩된 전체 URL 기준 약 8,000자)를 넘으면 전체를 클립보드에 복사하고 빈 새 채팅을 엽니다. 본문은 자르지 않습니다.
- 직접 입력한 프롬프트는 저장하지 않습니다. 새로고침이나 지우기로 사라집니다.
- 새 채팅 URL은 `https://chatgpt.com/?q=<텍스트>`와 `https://claude.ai/new?q=<텍스트>`입니다.

## Boundaries

- 로그인이 필요한 페이지와 JavaScript 렌더링이 필요한 페이지는 따로 처리하지 않습니다. 본문이 비거나 오류가 날 수 있습니다.
- 서버가 사용자가 준 임의 URL을 가져오므로 공개 배포하면 SSRF 위험이 있습니다. 이 저장소는 학습용이라 막지 않습니다.
- 테마 선택을 브라우저에 기억하는 것은 "프롬프트 저장 안 함"과 별개입니다.

## Why

브라우저에서 임의 사이트를 가져오면 CORS에 막히므로 서버에서 변환합니다. 잘라서 보내면 내용이 사라지고, 열기를 막으면 긴 글에서 핵심 기능을 못 쓰게 되므로 클립보드 경유를 택했습니다.

## Reconsider when

- `defuddle`이 Node에서 URL 입력을 공식 지원하거나, 쓰는 버전에서 위 동작이 달라질 때(0.19.6에서 확인).
- ChatGPT나 Claude가 `?q=` 동작을 바꿔 입력란이 비어서 열릴 때. 공식 API가 아닙니다.

## Evidence worth preserving

- `defuddle` 0.19.6에 URL 문자열을 직접 넘기면 실패했습니다. 블로그 글, Wikipedia(약 2,900단어), 최소 페이지는 DOM으로 넘기면 정상 변환됐고, 저자는 비어 있을 수 있습니다.
- `?q=`는 두 서비스 모두 로그인 리다이렉트에서 `q`가 유지되는 것까지만 확인했고, 로그인 상태에서 입력란이 채워지는지는 확인하지 못했습니다.
