# URL → Markdown → LLM 전달

웹 페이지 URL을 붙여넣으면 본문만 Markdown으로 추출해 보여주고, 복사·다운로드하거나 프롬프트와 함께 ChatGPT·Claude로 바로 넘긴다.

연결된 소스:

- `docs/specs/url-to-markdown/prototype.html` — 승인된 화면. 요소 배치와 순서, 상태별 모습(처음/변환 중/결과/긴 본문 결과/변환 실패), 다크모드와 좁은 화면에서의 쌓임을 정한다. 프로토타입의 더미 글, 변환 지연, "새 채팅을 열었어요" 알림 흉내는 화면 확인용이며 실제 동작이 아니다.
- `docs/decisions/ui-composition.md` — 화면 구성 요소, semantic token, 상태(loading/empty/error/success/disabled) 표현, 좁은 화면 쌓기 규칙을 정한다.
- `docs/decisions/dependency-versions.md` — 이 작업에서 새로 들이는 의존성의 버전 표기 방식을 정한다.

## 사용자가 얻는 결과

- URL 하나로 페이지의 광고·내비게이션을 걷어낸 본문 Markdown을 얻는다.
- 결과 화면에서 제목과 저자를 확인하고, 렌더링된 본문을 읽어 볼 수 있다.
- 결과를 클립보드로 복사하거나 `.md` 파일로 받을 수 있다.
- 선택한 프롬프트를 본문 앞에 붙여 ChatGPT나 Claude의 새 채팅으로 한 번에 넘길 수 있다. 본문이 길어도 잘리지 않는다.
- 밝은 테마와 어두운 테마를 바꿀 수 있다.

## 범위

포함:

1. **입력** — URL 입력 필드와 변환 실행, 지우기 버튼(입력과 결과를 모두 초기 상태로 되돌림).
2. **변환** — 서버에서 페이지를 가져와 `defuddle`로 본문을 Markdown으로 추출.
3. **결과 확인** — 헤더(페이지 제목, 저자) + 렌더링된 Markdown 본문.
4. **내보내기** — 복사하기, `.md` 다운로드, ChatGPT로 열기, Claude로 열기.
5. **프롬프트** — 프리셋 3종(요약해줘 / 한국어로 번역해줘 / 쉽게 설명해줘)과 "직접 입력". 선택은 선택 사항이며 아무것도 고르지 않으면 본문만 넘긴다.
6. **다크모드 토글**.

제외:

- 변환 기록, 계정, 저장된 사용자 프롬프트.
- 로그인이 필요한 페이지, JavaScript 렌더링이 필요한 페이지의 별도 처리.
- 여러 URL 일괄 변환.

## 수용 기준

화면 (승인된 `prototype.html` 기준)

- 한 페이지에 위에서 아래로 페이지 헤더(이름, 다크모드 토글) → 소개 문구 → URL 입력 → 결과 영역 순서로 놓인다.
- 결과 카드 안은 제목과 메타 줄(저자 · 사이트 · 도메인 · 단어 수) → "ChatGPT·Claude로 보내기" 구역 → "Markdown으로 내보내기" 구역 → 렌더링된 본문 순서다.
- "ChatGPT·Claude로 보내기" 구역은 제목과 설명(프롬프트를 맨 앞에, 그 아래 제목과 본문 전체) → 프롬프트 선택 → "보낼 내용" 미리보기 → ChatGPT로 열기 / Claude로 열기 버튼 순서다.
- "Markdown으로 내보내기" 구역은 제목과 설명(제목과 본문 전체가 담기고 프롬프트는 들어가지 않음) → 복사하기 / .md 다운로드 버튼 순서다.
- "보낼 내용" 미리보기는 실제로 보낼 두 부분을 순서대로 보여 주고, 프롬프트 선택이나 직접 입력 텍스트가 바뀌면 즉시 갱신된다.
  - 1번 프롬프트: 고른 프롬프트 문장. 고르지 않았으면 "없음 — 본문만 보내요". "직접 입력"을 골랐지만 비어 있으면 그 자리에 문장이 들어간다는 안내.
  - 2번 Markdown: 페이지 제목과 "본문 전체", 단어 수.
  - 전달 텍스트가 URL 한도를 넘으면 열기 전에 미리, 클립보드에 복사한 뒤 빈 새 채팅을 연다는 안내가 미리보기 안에 보인다.
- 아직 변환하지 않았을 때는 빈 상태 안내가 결과 자리에 보인다.
- 지우기 버튼은 입력값이 있을 때만 URL 입력란 안에 보인다.
- 좁은 화면에서도 이 순서를 유지한 채 쌓이고, 숨겨지는 요소나 버튼이 없다.

입력

- URL 입력 필드에 `http://` 또는 `https://` URL을 붙여넣고 변환을 실행할 수 있다.
- 입력이 비어 있으면 변환을 실행할 수 없다(disabled).
- `http(s)` URL 형식이 아니면 변환하지 않고 입력 필드 근처에 형식 오류를 보여 준다.
- 지우기 버튼을 누르면 입력값, 결과, 오류, 프롬프트 선택과 직접 입력 텍스트가 모두 초기 상태로 돌아간다.

변환

- 변환하는 동안 loading 상태가 보이고 변환 실행을 다시 누를 수 없다.
- `https://stephango.com/saw`를 변환하면 제목 "Use the saw, fear the saw", 저자 "Steph Ango"와 본문이 나온다.
- 존재하지 않는 호스트(예: `https://nope.invalid/x`), 응답 오류, 본문을 추출하지 못한 경우 각각 사용자가 이해할 수 있는 오류 상태를 보여 주고 다시 시도할 수 있다.

결과 확인

- 결과 헤더에 페이지 제목이 보인다. 저자가 있으면 함께 보이고, 없으면(예: `https://example.com`) 저자 자리를 비우지 않고 생략한다.
- 본문은 원시 Markdown 문자열이 아니라 렌더링된 형태(제목, 목록, 링크, 코드 블록 등)로 보인다.

내보내기

- 복사하기를 누르면 Markdown이 클립보드에 들어가고 복사 완료 피드백이 보인다.
- 다운로드를 누르면 페이지 제목을 바탕으로 한 이름의 `.md` 파일이 내려받아진다.
- 복사와 다운로드 내용은 페이지 제목(`# 제목`)과 본문 전체 Markdown이며, 프롬프트를 포함하지 않는다.
- ChatGPT·Claude로 보내는 본문 부분도 복사 내용과 같다(제목 + 본문 전체).
- "ChatGPT로 열기", "Claude로 열기"는 각각 새 탭에서 해당 서비스의 새 채팅을 연다.
  - 프롬프트를 골랐으면 전달 텍스트는 프롬프트 다음에 본문이 오는 형태다. 고르지 않았으면 본문만이다.
  - 전달 텍스트가 URL로 넘길 수 있는 한도 안이면 새 채팅 입력란에 그 텍스트가 채워진 상태로 열린다.
  - 한도를 넘으면 전달 텍스트 전체를 클립보드에 복사하고, 빈 새 채팅을 열고, "클립보드에 복사했으니 붙여넣으세요"라는 안내를 보여 준다. 본문은 잘리지 않는다.

프롬프트

- 프리셋 3개와 "직접 입력"이 나란히 보이고, 하나만 선택되거나 아무것도 선택되지 않는다. 선택한 항목을 다시 누르면 선택이 해제된다.
- "직접 입력"을 고르면 텍스트 입력이 나타나고, 그 텍스트가 프롬프트로 쓰인다.
- 직접 입력 텍스트는 저장하지 않는다. 새로고침하거나 지우기를 누르면 사라진다.

다크모드

- 토글로 밝은/어두운 테마를 바꿀 수 있고, 모든 화면 요소가 두 테마에서 읽힌다.

## 정해진 제약과 이유

- **본문 추출은 `defuddle`로 한다.** 사용자가 필수로 지정했다. scratch에서 `defuddle` 0.19.6 + `linkedom`으로 확인했다.
  - URL 문자열을 `defuddle/node`에 바로 넘기면 실패했다. 서버에서 HTML을 가져와 DOM으로 파싱한 뒤 넘겨야 동작했다.
  - 블로그 글, Wikipedia(약 2,900단어), 최소 페이지가 정상 변환됐다. 저자는 비어 있을 수 있다.
  - 다시 볼 조건: `defuddle`이 Node에서 URL 입력을 공식 지원하거나, 사용 중인 버전에서 위 동작이 달라질 때.
- **페이지 가져오기와 변환은 서버에서 한다.** 브라우저에서 임의 사이트를 가져오면 CORS에 막히기 때문이다.
- **긴 본문은 잘라 넘기지 않는다.** URL 한도를 넘으면 클립보드 복사 후 빈 채팅을 연다. 사용자가 확정했다. 잘라서 넘기는 방식은 내용 손실 때문에, 열기를 막는 방식은 긴 글에서 핵심 기능을 못 쓰게 되기 때문에 택하지 않았다.
- **직접 입력 프롬프트는 저장하지 않는다.** 사용자가 1회용으로 지정했다.
- 화면 구성은 `docs/decisions/ui-composition.md`를 따른다.

## 가정 (덮어쓸 수 있음)

- ChatGPT는 `https://chatgpt.com/?q=<텍스트>`, Claude는 `https://claude.ai/new?q=<텍스트>`로 입력란을 채운 새 채팅을 연다. 구현 때 실제로 열어 확인하고, 다르면 이 가정을 고친다.
- URL로 넘길 한도는 인코딩된 전체 URL 기준 약 8,000자로 잡는다.
- 프롬프트와 본문 사이는 빈 줄로 구분한다.
- 테마 선택은 브라우저에 기억하고, 처음 방문하면 시스템 설정을 따른다(이 기억은 "저장하지 않음"이 걸린 직접 입력 프롬프트와 별개다).
- 다운로드 파일 이름은 페이지 제목에서 파일명에 쓸 수 없는 문자를 뺀 값이고, 제목이 없으면 도메인을 쓴다.
- 페이지를 가져올 때 응답 대기 한도는 15초다.

## 손대지 않을 영역

- `docs/decisions/dependency-versions.md`가 정확한 버전으로 고정한 `next`, `react`, `react-dom`, `eslint-config-next`는 이 작업으로 올리지 않는다. 버전을 바꾸면 강의 화면이 수강생 환경과 달라진다.

## 남은 위험

- ChatGPT·Claude의 `?q=` 동작은 공식 API가 아니다. 서비스가 바꾸면 입력란이 비어서 열릴 수 있다.
- JavaScript로 본문을 그리는 페이지나 봇을 막는 사이트는 본문이 비거나 오류가 날 수 있다.
- 서버가 사용자가 준 임의 URL을 가져오므로, 공개 배포하면 내부망 주소 요청(SSRF) 위험이 있다. `AGENTS.md`의 검증·리뷰 예산상 이 스펙은 막지 않는다.
